# Pi-Archiver Ultra

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Инновационный архиватор, использующий число π в качестве универсальной базы данных для сжатия файлов. 
Проект находится в активной разработке.

## 📦 Возможности

- [x] Базовое сжатие файлов с использованием числа π
- [x] Поддержка файлов любого типа и размера
- [x] Разбиение на блоки 4-16 байт
- [x] Поиск последовательностей в цифрах π
- [x] Формирование индексного файла в формате JSON
- [ ] Восстановление файлов из архива (в разработке)
- [ ] Поддержка GPU (AMD Fury X)
- [ ] Параллельная обработка на многоядерных процессорах

## 🚀 Установка

1. Клонируйте репозиторий:
```bash
git clone https://github.com/yourusername/pi-archiver-ultra.git
cd pi-archiver-ultra
```

2. Установите зависимости:
```bash
pip install -r requirements.txt
```

## 🛠️ Использование

### Архивация файла
```bash
python src/main/archiver.py compress input_file.txt
```

### Разархивация (в разработке)
```bash
python src/main/archiver.py decompress input_file.piarc
```

## 🏗️ Архитектура

```
Pi-Archiver Ultra
├── Pi-Generator (генерация π)
├── Search-Engine (поиск последовательностей)
├── Compression-Core (сжатие и упаковка)
├── DSP-Module (вычисления на GPU)
└── Index-Manager (управление метаданными)
```

## 📝 Реальный пример сжатия

### Пример индексного файла (test_file.piarc.idx):
```json
{
  "files": [
    {
      "filename": "test_file.txt",
      "original_size": 241,
      "compressed_size": 240,
      "blocks_count": 24,
      "compression_ratio": 1.0041666666666667,
      "pi_precision": 63,
      "blocks": [
        {
          "block_id": 0,
          "start_pos": null,
          "end_pos": null,
          "compressed_size": 10,
          "data_hash": "13497316",
          "original_size": 10
        }
        // ... остальные блоки
      ]
    }
  ],
  "pi_precision": 1000000,
  "created_at": 1766132519.2658076,
  "total_blocks": 24,
  "compression_ratio": 0.995850622406639
}
```

### Особенности работы с маленькими файлами:
- **Эффективность сжатия**: Для очень маленьких файлов (менее 1 КБ) коэффициент сжатия может быть близок к 1 или даже больше из-за накладных расходов на метаданные.
- **Размер блока**: Минимальный размер блока - 4 байта. Для файлов меньшего размера сжатие нецелесообразно.
- **Накладные расходы**: Каждый блок добавляет ~50-100 байт метаданных, что критично для маленьких файлов.
- **Рекомендации**: 
  - Для файлов < 1 КБ используйте стандартные архиваторы (ZIP, RAR)
  - Оптимальный размер файла для Pi-Archiver: от 10 КБ
  - Группируйте маленькие файлы в один архив перед сжатием
